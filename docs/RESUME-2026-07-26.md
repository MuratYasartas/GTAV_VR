# GTAVR — Reprise 2026-07-26 (matin)

## Où on en est (au coucher)

- Tout le pipeline VR marche SAUF la consommation caméra par le renderer :
  injection, OpenXR session Focused, AER actif, overlay (input bloqué pendant
  l'ouverture, sliders affinés), caméra RÉSOLUE (pattern b3889, 17k+ writes).
- DIAG prouvé : notre écriture dans `camBase+0x1F0` PERSISTE (le jeu ne
  l'écrase pas) mais **le renderer ne la lit pas**.
- Pokes externes (rotation 90°/180°, boucles 10-60 s) : AUCUN effet visuel
  sur +0x30, +0xA20, +0xD70, +0x1080, +0x13B0, +0x1A30, +0x1D30, +0x60
  de l'objet caméra actuel, ni sur le candidat quaternion 0x1E5185A22BC.
- Le pattern original `CViewPort::GetCamera` (6DoF historique, +0x60) est
  ABSENT du build 3889.
- Conclusion : la vue de rendu est recomposée par le moteur (pas de matrice
  mémoire directement patchable trouvée) → **pivot stratégique : ScriptHookV**.

## ScriptHookV (prêt à installer)

- Téléchargé : `build_int/scripthookv_dist/bin/` = dinput8.dll (ASI loader),
  ScriptHookV.dll, NativeTrainer.asi, xinput1_4.dll. Version v3889.0/1158.13
  = supporte exactement le build 1.0.3889.0. Story-mode only par conception
  (compatible avec notre OnlineGuard).
- INSTALL (admin) : copier les 4 fichiers de `bin/` dans
  `D:\Rockstar Games\Grand Theft Auto V Legacy\` (sauf NativeTrainer.asi,
  optionnel). Vérifier : le jeu démarre, le trainer F4 répond.
- SDK déjà en repo : `ThirdParty/scripthook/inc/` (natives.h etc.).

## Ne pas oublier

- Le slot pointeur caméra est NULL pendant le chargement — résolution seulement
  une fois en jeu (retry 60 s gère).
- `desktopMirrorSyncOverride=1` par défaut (pacing). `GTAVR_VERBOSE` via ini.
- Game dir non inscriptible par l'utilisateur normal → install ScriptHookV
  en admin (comme pour dxgi.dll).
