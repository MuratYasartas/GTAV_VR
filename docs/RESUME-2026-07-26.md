# GTAVR — Reprise 2026-07-26 (soir)

## 2026-07-30 — CORRECTION de l'audit Euler précédent

- Les conclusions `9abf3c2` / `bca8773` ci-dessous sont conservées comme
  historique mais **supplantées** : l'ordre GTA 2 est `ROT_ZXY`, donc en
  DirectX row-vector **M = Rz·Rx·Ry**, pas `Rz·Ry·Rx`.
- La production utilise maintenant cet ordre et un test oracle développe la
  matrice explicitement afin de ne plus valider une formule par elle-même.

## 2026-07-27 — AUDIT recenter : la vraie cause (fix commité `9abf3c2`)

- Le bug recenter ("image de travers") était **conventionnel, pas logique** :
  le bridge lisait `GET_GAMEPLAY_CAM_ROT` en ordre **0 (XYZ)**, mes formules
  supposaient **ZYX (ordre 3)**, et `SET_CAM_ROT` écrit en **ordre 2 = ZXY**
  (défaut des natives GTA). Pitch+yaw non-nuls → base mal décomposée.
- Fix : tout en **ZXY (ordre 2)** — bridge GET avec `nativePush64(2)`,
  VRCamera `M = Ry*Rx*Rz`, extraction pitch=asin(fwd.z),
  roll=atan2(-right.z, up.z), yaw=atan2(-fwd.x, fwd.y).
  Tests ZXY (`build_int/verify_vrcamera_math.py`) : ALL PASS.
- **À vérifier au prochain test casque** : recenter (doit être propre),
  tracking inchangé (la composition physique était déjà juste — seule la
  décomposition Euler changeait).
