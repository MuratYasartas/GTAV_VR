Observations (appended by the Phase 9/10 workstream after the official run)
============================================================================

1. Why every run is inert-clean on the slice (NOT an OVRInject bug):
   D3D11Cube creates its D3D11 device well under 1 s after process start.
   Every supported load path is asynchronous and completes later:
   - CreateRemoteThread injection: remote LoadLibrary of OVRInject.dll +
     its import chain (dbghelp, openvr_api, openxr_loader) ~100 ms+, then
     DllMain -> InitThread installs the creation hooks.
   - Shim (dxgi proxy): DllMain Sleep(250) + modal MessageBox + the same
     deferred LoadLibrary -> hooks land ~1 s after process start.
   The Present-hook creation hooks therefore always arrive after the
   swapchain exists, and the 30 s swapchain watchdog parks the mod inert
   exactly as designed (D3DHooks_VRManager.hpp). Against GTA V (minutes of
   startup before D3D init) the same flow is expected to end
   hook-success + inert-VR pass-through. Hook-success on the slice is
   structurally unreachable without modifying the slice or OVRInject, so it
   is UNVERIFIED here; the watchdog inert path is verified 20/20 (plus
   launcher-first and shim modes, 3/3 in a follow-up mixed run).

2. No crashes, hangs, minidumps, or teardown failures were observed in any
   run; every cube process died within the 10 s kill window. No
   OVRInject-internal bugs found -> nothing to fix (and OVRInject was not
   modified, per wave ownership).

3. OVRInjectShim note (shipped loader, owned by another workstream):
   OVRInjectShim/Log.cpp LOGWNDF pops a MODAL MessageBoxA ("Found GTA5.exe
   with shim DLL, injecting main DLL..") on every successful shim injection.
   On an unattended machine this stalls mod loading until someone clicks OK.
   The harness auto-dismisses it in shim mode. Worth replacing with a
   file-only log in the shipped build.

4. Manifest layout note: OVRInject/Game/BuildManifest.cpp resolves
   gtav_legacy.ini only as <GTAVR_SETTINGS_DIR|game exe dir|dll dir>\
   gtav_legacy.ini (root), while the documented/installer layout ships a
   manifests\ folder. tools/install.bat therefore copies BOTH
   manifests\gtav_legacy.ini (documented layout) and a root
   gtav_legacy.ini (what BuildManifest actually reads). The launcher
   preflight checks both locations.
